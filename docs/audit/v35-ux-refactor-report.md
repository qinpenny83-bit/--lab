## 一、回答 10 个验收问题

### 1. 首页现在的核心学习路径是什么？

首页不再平铺「推理 / 分析 / 学习 / 案例 / 复习」等入口，而是围绕一条弧线：**今日修炼主路径 = 先学 → 观察 → 练习 → 案例 → 推理 → 迁移 → 复习**。

具体实现（`HomePage.tsx`）：
- 自动定位「当前境界 → 当前章节 → 下一个未完成的学习单元」，作为今日焦点；
- 当前境界走完自动推进到下一境第一章；
- 首屏展示「今天学什么」（焦点标题 + objective）、「为什么现在学」（自然语言，来自真实前置关系与进度）、「今天你会」（未来最多 4 步动作预览去重）、「预计时长」；
- `开始今日修炼` 直跳 `/course/:chapterId`（进入对应的 Stage5 课程播放器）。

### 2. 小白第一次进入时会看到什么？

冷启动状态下（`currentStageId=stage1`，无任何完成记录）：
- 首屏焦点是**初识中医第一课**（第一章第一个未完成单元），标题 + 一句 objective；
- 「为什么现在学」给出自然语言："这是『初识中医』的第一课。中医不是靠背的，你要先学会『用中医的方式看身体』，后面每一境都建在这一步上。"
- 「今天你会」提示这一小段学习弧线的前几步动作；
- 一个大号主按钮「开始今日修炼 →」；
- 下方克制地显示「你的修炼状态」（境界 + 进度条 + 最近掌握）与「查看修炼之路」链接；
- 底部低调陈列 5 个探索入口（知识地图 / 经典 / 方剂 / 反直觉 / 家庭观察），不抢占主路径。

### 3. 「分析」和「推理」现在分别承担什么角色？

- **分析 = 教练带你看**：`LearningUnitPlayer` 中的 `read` / `think` / `observe` 单元承担"被引导地理解"，系统逐步揭示（`think` 的 reveal 引导、`observe` 的开放性观察），不要求用户承担全部认知负担。
- **推理 = 轮到你来**：`case_analysis` 单元进入 `ReasoningPlayer`，用户自己「找线索 → 选关键 → 定主次 → 建假设 → 找证据 → 找反证 → 修正 → 综合解释」，并在进入前有明确的「心理转场」。
- 说明：两者边界已被结构（单元 `interactionType`）与路由（`LearningUnitPlayer` vs `ReasoningPlayer`）显性分离，但「分析 = 教练带看的四步（现象→关键线索→关系→理论解释）」尚未做成一个独立命名的"分析"模式，目前由 read/think/observe 组合承担（见缺口 ⑩·A）。

### 4. 推理为什么放在学习之后？

因为推理是"能力训练"而非"知识入口"，必须建立在"已经理解、已经观察、已经练习"之上，才能让用户产生"我刚学会这个，现在让我试试看能不能用"的奖励感，而不是"还没学就要做题"的挫败。实现上：`ReasoningPlayer` 通过 `case_analysis` 单元接入，而 `case_analysis` 单元在章节内排在 `introduction/why/concept/observation/check/explanation/paradox` 之后（`lu-s5-qj-08`），且 `prerequisiteIds` 串起了前面全部单元，形成"先学后推理"的硬顺序。

### 10. 目前还存在什么 UX 问题？

如实列出，均未隐藏：

**A. 「分析」与「推理」的边界未做成显式"分析模式"。** 用户要求"分析=教练带你看（现象→关键线索→关系→理论解释）逐步揭示"，目前由 read/think/observe 三类单元近似承担，缺少一个统一命名的"带你看"流程容器。属于"能力存在、表达未统一"。

**B. 答错复盘的五段式未完全闭合（验收标准 E）。** 原要求"我的判断 → 忽略的线索 → 为什么重要 → 理论解释 → 再尝试"。`ReasoningPlayer` 最终有「🧭 推理复盘 + rootCause + correctReasoning + 慢下来微训练 + 再试一次」，`LearningUnitPlayer` 多选答错有"再想一次会更好 + explain"。但"**你注意到了 A，忽略了 B；如果没有 B，原判断是否仍成立？**"这种逐条苏格拉底式追问尚未做成独立交互步骤，目前以 rootCause/correctReasoning 的概括形式呈现。

**C. 动态按钮文案未完全对齐。** 用户要求"开始学习 / 我想好了 / 查看解释 / 开始练习 / 进入案例 / 开始推理 / 尝试迁移 / 完成复习"，现有实现部分对齐（"我想好了，看看教学引导""提交我的判断""记录我的解释并继续""好，开始找线索"），但仍残留多处"进入下一步 → / 继续 →"这类"下一步"措辞（read 单元、说明分支等），与"不要让课程像 PPT"的要求有出入。

**D. Agent 隐形干预覆盖面偏窄（验收标准 F 部分满足）。** `coachDecision` 的"改变下一步"仅在 `ReasoningPlayer` 结案时呈现（`coachReason` + `premature_judgment` 触发"🐢 慢下来微训练"并暂锁"进入迁移"按钮）。日常练习单元里，Agent 尚未形成同等的"按错因调整下一步"的显性路径变更。满足"至少验证一次路径不同"，但未贯穿全流程。

**E. 新增 UX 验收测试未落地。** 本轮未新增独立的 `acceptance-ux` 测试文件（现有为 V2/V3/V35 三套）。UX 层的不变式（4 项导航、主 CTA、当前一步、心理转场、8 层徽章）目前靠代码人工核对，未固化为自动化测试。

**F. 移动端 390px/768px 未真机复核。** CSS 已加入 `max-width: 479px` 断点与单列布局，但真机/浏览器未验证，不能确认"无横向滚动、推理工作台可操作"。

**G. 首屏仍保留 5 个探索入口 + SafetyNote。** 已收敛为低调陈列，符合"知识/经典作为探索型入口"的定位，但严格意义上首屏仍非100%单一焦点，属可选再收敛项。
